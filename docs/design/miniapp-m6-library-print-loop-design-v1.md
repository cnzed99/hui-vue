# M6 文库详情与去打印闭环设计 v1

日期：2026-10-31
状态：Astra High 设计审查修订中

## 目标

把小程序文库从本地列表 fixture 升级为新系统自有演示文库：服务端目录与搜索 → 文库详情/逐页预览 → 去打印生成当前演示主体的私有 PDF → 既有打印设置、权威计价、订单、模拟支付、配套后台唯一任务/回执 → 小程序结果恢复。

## 原系统只读观察基准

- 列表：橙色“文库”标题；文件名搜索；分类、本店、不限、排序四项筛选；卡片包含缩略页、标题、`分类 @ 文库名`、浏览/打印数和页数。
- 详情：标题“文件预览”；页面纵向预览并带“第 N 页”角标；底部固定“收藏、分享、去打印”。
- 本轮只打开列表和首个详情，没有点击收藏、分享或去打印，没有输入搜索、上传、下单、付款或修改原数据。

## 数据与版权边界

- 不复制原文库 PDF、缩略图、对象存储 URL、token、真实统计或历史数据；不把观察到的真题内容作为新系统资源。
- 新系统内置 3 个自有演示条目，使用中性标题、分类、来源和原创简短正文；条目 ID 与内容版本固定，便于可重复生成 PDF。本批目录只是公开的新系统固定演示资源，不是真实商家/门店文库，不能借此扩展成跨店资源访问。
- 列表中的浏览/打印统计标记为演示值或零，不因读取详情写入统计。收藏依赖正式微信身份，当前返回 `RESERVED_WECHAT_IDENTITY`；分享只在微信构建保留系统分享入口，H5 和未配置 AppID 时明确 `NOT_RUN`。

## 服务端接口

### 只读目录

- `GET /app-api/print/miniapp/demo/library?pageNo=&pageSize=&keyword=&category=&sort=`：只返回内置演示条目；严格白名单参数，pageSize 1–20；排序只允许 `DEFAULT`、`TITLE_ASC`、`PAGES_ASC`。本里程碑只实现有明确契约的搜索、新系统静态分类和排序；观察页面上的“本店/不限”只记录为待补充只读观察的原系统控件，未确认前不猜测其业务含义、不将其标记为已完成功能。
- `GET /app-api/print/miniapp/demo/library-entry?id=...`：返回单个条目、页面预览模型、固定 capability，不返回源文件路径或正文全文。
- 两个只读接口不访问原系统，不访问历史表，不写浏览量；响应 `no-store`。
- 后续如接入真实门店文库，必须另行增加会话租户/门店作用域和数据库约束，并按 Astra High 权限隔离条件重审；本批不预留可以越过该审查的通用真实资源接口。

### 去打印文件生成

- `POST /app-api/print/miniapp/demo/library-files`，严格 `application/json`，body 只能为 `{ "entryId": "..." }`；要求有效演示会话、Origin/Host 和 `Idempotency-Key`。
- 服务端只按受信静态条目查找正文，客户端不能提交正文、URL、对象存储键或文件路径；不存在条目统一 404。
- 复用同一个 Spring 单例 `MiniappDemoTextPdfRenderer` bean 及其既有信号量/忙状态保护，不复制排版器、不在业务中 `new` 新实例。渲染输入只能由服务端静态条目构造。生成 1–3 页 PDF 后调用既有 `MiniappDemoFileService.upload`，文件继续受 2MB、20页、1小时、每主体3个活动文件、磁盘阈值、解析队列与幂等约束保护。
- 受信渲染模型必须将 `entryId + contentVersion` 写入确定性 PDF 内容/元数据指纹，并继续以生成 PDF 的 SHA-256 作为既有上传请求指纹。因此同主体、同幂等键、同条目与同内容版本才重放同一文件；同键换 `entryId` 或 `contentVersion` 必须触发既有 409 幂等冲突，即使两条正文恰好相同也不得误重放。
- 已发布的 `entryId + contentVersion` 内容冻结；任何正文、标题或排版输入的实质变更必须显式升级 `contentVersion`。旧键对旧版本可重放旧文件；如同键请求已变版本则返回 409，不静默用新内容覆盖旧请求。
- 条目预览模型页数必须与服务端固定 `expectedPageCount` 一致；生成文件只有在既有异步解析进入 `READY` 且解析页数等于该值时才可进入打印设置。`FAILED`、`DELETED`、超时或页数不符都停在本页告警，不传入报价/订单。
- 并发收敛、跨主体读取隐藏和过期清理完全复用既有文件链。
- 显示文件名来自服务端静态安全值，不采用客户端输入。

## 小程序页面

- 列表从服务端读取；搜索以及本批明确定义的静态分类/排序真实生效。“本店/不限”保留观察记录但显示待确认边界，不做虚假筛选。服务不可用时显示明确错误/重试，不把旧 fixture 冒充服务端结果。
- 新增 `/pages/library-detail/index?id=...`：复刻文件预览、页码角标和固定底栏；预览内容使用自有演示模型，不嵌入原站或第三方 PDF。
- 收藏按钮显示“微信身份接入后开放”，不写本地假收藏；分享在 MP-WEIXIN 使用 `open-type="share"` 与固定条目路径，H5 显示真机边界，未验证前保持 `NOT_RUN`。
- “去打印”调用 `library-files`，轮询到 READY 后只保存文件元数据草稿并进入既有打印设置；后续金额、订单和打印状态完全由现有服务端链路决定。
- 一次用户意图从首次提交到超时重试必须保留同一 `Idempotency-Key`；只有用户明确再次点击产生新意图时才创建新键。`FAILED` 或 `DELETED` 是该文件的可见终态，不得在后台自动换键重新生成。
- 页面隐藏/卸载使请求代次失效，旧响应不能覆盖新条目；演示会话变化时不沿用旧文件或订单上下文。

## Nginx 发布边界

- M6 必须从实际启用的 M5 全链路配置 `/etc/nginx/sites-available/print-system` 复制候选，基线 SHA-256 为 `b46ff356f256d6669c09ec136fe17e550a2131495208b35b9e684643dc832c60`；只追加本批三个精确 location，不使用只含 M3 局部路由的旧文件作基线，不得删除 M2–M5 文件、报价、订单、支付、任务或结果入口。限流基线为实际启用的 `/etc/nginx/conf.d/print-miniapp-limits.conf`，SHA-256 为 `4a44da59ef06da642854d662bd6018d672ffda0680a5a43e7866588e4017aeb5`。
- 仅新增三个精确 location：library GET、library-entry GET、library-files POST；相邻路径继续由 `/app-api/` 兜底 404。GET location 必须显式排除 Nginx 默认允许的 HEAD，非精确 GET 一律 403。
- library-files 非 POST 全部 403，限制请求体 2KiB（超限由 Nginx 返回 413）、连接/发送/读取超时，并复用文件生成限流区；只读端点非 GET 全部 403。
- 转发 Authorization（只读接口允许缺省）、Origin、Host；响应统一 no-store、nosniff、same-origin。不得使用宽前缀代理。

## 错误与日志

- 沿用既有错误语义，不为文库改底层异常：参数无效 400、会话无效 401/403、条目不存在 404、幂等冲突 409、Nginx 2KiB/生成 PDF/页数超限 413、排版器繁忙或主体活动文件上限 429、存储服务不可用 503、磁盘容量保护 507。异步解析失败不在 create 响应伪造同步 422，而是在文件元数据中进入 `FAILED + failureCode`。
- 控制器对请求/响应业务日志关闭；异常只记录固定码和异常类型，不记录静态正文、PDF 字节、token 或文件路径。
- 新 POST 沿用当前 TextController 的防护模式：不用 `consumes` 使错误请求绕过局部日志关闭；全部 POST 先进入局部控制器，再严格验证 Content-Type、无额外 query、无重复 JSON 字段、无尾随 JSON 以及体积上限。GET 搜索词和筛选参数不写入业务日志；分享路径只能携带公开 `entryId`，不得携带会话、文件、报价、订单或支付标识。
- 原系统 URL、对象存储域名、观察 token 和真实条目正文不得进入源码、配置、测试或证据。

## 审查与验证

1. Astra High 先审新增写入口、会话/主体隔离、幂等/并发、复用计价和打印防重复的设计；实现后审最终差异与证据。
2. 服务端：目录参数白名单、条目详情、生成文件、同键重放/冲突、并发收敛、跨主体隐藏、活动文件上限、固定错误、无原站依赖。
3. 小程序：type-check、H5、mp-weixin；列表搜索/筛选、详情预览、返回、真机边界和去打印状态机。
4. 运行：Nginx 精确方法/相邻路径、no-store、服务重启后相同条目 PDF 确定性、日志无正文/凭据。
5. 浏览器闭环：文库 → 详情 → 去打印 → 设置 → 权威报价 → 订单 → 模拟支付 → 后台唯一任务/模拟回执 → 小程序恢复。
6. 负向与稳定性：响应丢失保持同键重试，同键不同条目/版本冲突；文字、上传、文库共用同一活动文件上限和 renderer 并发资源；三个原创条目的预览、PDF 与解析页数一致；重启后相同输入摘要一致，既有 M2–M5 路由仍可达。

## 明确 NOT_RUN

- 原文库文件复制或同步
- 正式对象存储/CDN
- 微信真实登录、收藏同步和分享落地
- 原系统“本店/不限”筛选的确切业务语义（待补充只读观察，不计入本里程碑完成）
- 真实支付/退款
- 真实打印机
- 微信开发者工具/真机
- 外部用户验收
