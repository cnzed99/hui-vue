# ZIP-PDF 开发候选部署与回退计划

状态：待 Astra High 复审。本文是操作计划，不能作为执行授权。目标仅为用户开发演示环境，继续使用 loopback/既有 SSH 隧道。正式环境、正式库、微信真机、真实支付及打印设备均不在本计划范围。

## 开始前

1. 由实施者提供经独立审查的后端提交、JAR SHA-256、SQL 与两份 Nginx 片段 SHA-256，以及配套 H5 构建和对应提交。使用正式上线之外的开发窗口，确认目标主机、实例、库、存储根、候选版本和活动版本。审查或授权缺项时停在计划阶段。
2. 核实当前健康与空闲磁盘。四服务均 active，后端内部健康端点返回预期，磁盘最低保留 10 GiB。确认不存在其他构建、迁移或部署窗口。先识别当前后端 JAR/服务引用、H5 发布目录及其符号链接、活动 Nginx 配置与 include 关系、DB 文件表保护、上传和 PDF worker 状态。任何识别信息不包含凭据。
3. 将候选 JAR、H5、SQL、Nginx 片段放到各自独立候选路径，核验摘要。先在隔离配置运行 `nginx -t`，校验全局 zone、两条精确 location 与通用 404。不得新增公开监听或扩大 Origin/Host 白名单。
4. 在验证过的备份目录记录旧制品指针、环境文件引用、配置摘要、文件存储范围及数据库结构版本。做完整且可还原的开发库备份，必要时备份与数据库引用配套的上传对象。备份限定权限、禁止入 Git。备份前后检查磁盘和可恢复性。没有可验证备份不开始迁移。

## 增量 DDL 与服务切换

1. 在开发演示窗口关闭新上传入口并排空已有请求。确认没有活动 ZIP 请求、普通上传或 PDF worker 正在写入。保留现有数据库和对象，停开发后端后再次核对进程状态。此窗口禁止其他实例连接同一开发文件存储根。
2. 对正确的开发库执行只读 preflight。检查 MySQL 8、InnoDB、目标表存在、当前文件行数量、原有约束及原幂等唯一索引列顺序 `(tenant_id, store_id, principal_id, idempotency_sha256)`。核实 `archive_sha256`、`archive_entry_ordinal` 与 `chk_print_demo_file_archive_source` 均不存在。若三者已全部存在，只在类型、ASCII 二进制比较、可空性、序号范围、CHECK 生效和现存数据完全一致时视为已应用。半应用、漂移、锁等待或预检不符即停止。
3. 仅对已授权的开发库运行准确版本的 `ops/db/print-miniapp-demo-archive-provenance.sql`。这一步只添加两个可空字段和一个成对来源约束。再次核实既有唯一索引、原保护约束、记录数以及旧行来源为 NULL。检查新 CHECK 为 ENFORCED，序号范围为 0–19，半空来源拒绝。应用包必须在确认迁移成功后才启动。失败时先读取元数据确认状态，禁止盲目重试。
4. 确认 Nginx worker 的实际用户及组。独立目录 `/var/lib/nginx/print-miniapp-archive-body` 必须归该用户及组、模式 0700，且在已核实的真实父路径内，不是符号链接。仅当目录不存在时按确认的 worker 身份创建。已有目录如果属主、权限或路径不符，停止并检查，不自动改权或清空。
5. 新旧 Nginx 片段按版本存放。全局 `limit_conn_zone` 仅在 http 上下文加载一次，两个 archive location 只在开发站点 server 内加载，并共享全局上限 2、单地址上限 2 和专属 body 临时目录。请求上限为 2100 KiB。开启入口前以活动配置候选做 `nginx -t`。临时目录不得和 Nginx 默认目录、其他上传路由或 Servlet multipart 目录共用。
6. 启动候选开发后端。核对独占存储锁、数据库/schema、端口和真实健康状态。先保留旧 H5 与旧边缘路由，验证既有 PDF 上传及后台读路径。再加载精确路由，执行 Nginx reload 并等旧 worker 自然排空，然后切换 H5 指针。只在两个新路由与候选应用契约匹配后放开新入口。

## 验证与故障处理

- 真实健康：四服务 active，Nginx 登录页及后端健康端点返回预期。检查新 ZIP URI、既有普通上传、通用 `/app-api/` 404 以及不允许的方法和无会话请求。
- 使用合成 ZIP 完成检查、选择、READY、报价、订单、模拟付款、后台领取/执行、模拟回执及 H5 结果。确认同键重试和无效输入拒绝，核对普通上传回归。真实微信未执行时保留 NOT_RUN。
- 核对临时容量与运行期间目录归属。隔离证据覆盖两条慢请求占用独立 body 文件描述符、第三条 429、断连后恢复以及隔离实例 SIGKILL 重启零残留。活动站点不做 SIGKILL 演练。
- 正常 reload 必须给旧 worker 处理在途连接的时间。重启后读取专属目录和相关进程打开的文件描述符。只有全部相关 worker 退出、专属目录路径和归属已验证、确认不存在打开的文件且有明确清理授权后，才处理该目录内确属本功能的遗留文件。发现异常先关闭 ZIP 入口并保全证据。不遍历或清理共享 multipart root。
- 后端、数据库或边缘异常时，先封闭两个 ZIP 路由并撤回 H5，再等待已接收的请求实际结束。恢复旧 Nginx 配置并通过 `nginx -t`，恢复已知健康的旧后端和 H5 引用，复核四项服务及既有上传。
- 回退默认保留新增可空列及 CHECK。旧 JAR 忽略新增列，已保存的 ZIP 来源或幂等记录必须保留。若已有 ZIP 来源记录，且回退版本未比较来源字段，恢复旧 JAR 时同时保持普通上传写入关闭，避免同主体用 ZIP 键跨到旧普通上传路径重放。待支持来源校验的修复版本通过审查和烟测，再恢复写入。若确需恢复旧 schema，必须另行取得授权和 Astra High 审查，在独立恢复环境验证备份与文件配套后另订迁移计划。不得使用删列、删行、覆盖数据或盲目回放备份作为常规回退。
- 保留候选与回退版本、备份引用、预检与迁移结果、烟测、磁盘和健康证据。摘要和日志必须脱敏。范围外发布、不可逆迁移或真实业务接入均不在此次授权内。
