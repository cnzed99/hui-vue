# 证件照服务端文件部署与回滚计划

状态：开发候选，尚未迁移或部署。生产执行前必须获得 Astra High 最终审查 PASS。

## 不变量

- 证件照文件只进入共用文件存储根目录下的 `id-photo-multipart/task-*` 与 `id-photo-scratch/task-*` 私有临时目录。
- 正常运行、迁移、失败回滚和旧版恢复均不得遗留原始照片或中间 PDF。
- 清理程序必须取得文件服务使用的同一 `.worker.lock` POSIX 记录锁；锁被占用时退出，不得强删。
- 清理只接受真实目录，拒绝符号链接和特殊文件；只删除两个受管目录直属的 `task-*` 子树。
- 普通文件对象和数据库记录不属于回滚清理范围。
- 数据库迁移保持增量；应用层与数据库触发器都禁止证件照进入计价、订单或支付。

## 部署顺序

1. 停止入口流量并停止后端，确认没有文件任务进程。
2. 备份数据库与当前 JAR，记录哈希；不修改备份。
3. 执行增量迁移并核对列、约束和触发器。
4. 启动候选 JAR，等待 `Started YudaoServerApplication`，再连续两次验证 catalog 合同。
5. 验证证件照生成文件成功、证件照计价被应用层与数据库层同时拒绝。
6. 恢复入口流量；持续观察错误率和私有临时目录。

## 失败回滚顺序

1. 停止入口流量并停止候选后端；等待进程完全退出。
2. 执行 `python3 ops/runtime/cleanup-id-photo-private-tasks.py <文件存储根目录>`。
3. 只接受 `ID_PHOTO_PRIVATE_ROLLBACK_CLEANUP_PASS`；若返回锁占用、非安全目标或其他错误，保持停机并人工核查，不启动旧 JAR。
4. 启动旧 JAR并等待 catalog 合同连续两次成功；旧 JAR遇到证件照来源行时必须安全拒绝，不能创建报价。
5. 数据库新增列和保护触发器默认保留；未经新的 Astra High 审查不得撤除或放宽触发器。
6. 核对两个私有目录无 `task-*`，再恢复入口流量。
