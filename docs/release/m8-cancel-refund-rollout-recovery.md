# M8 取消与模拟退款发布/恢复方案

状态：`CANDIDATE_NOT_DEPLOYED`

适用范围：新系统 MINIAPP_DEMO 数据。真实支付、真实退款和真实打印设备均不在本批范围。

## 门禁

1. 最终源码、SQL、并发/账务验证及本方案取得 Astra High `PASS`。
2. 生成并验证数据库备份；记录备份哈希和恢复演练结果，不把凭据写入仓库。
3. 标准构建窗口持有唯一锁；停止后端、MySQL、Redis、Nginx，构建完成后恢复四项服务并等待健康端点就绪。
4. 应用迁移时取消 POST 功能开关保持关闭。

## 分阶段发布

1. 运行 `print-miniapp-demo-cancellation-refund-preflight.sql`，全部 `violation_count` 必须为 0。
2. 备份并验证后应用 `print-miniapp-demo-cancellation-refund-v1.sql`。
3. 校验三张新表、外键、CHECK 和不可变触发器；确认 M8 三表均为 0 行。
4. 部署可读取旧/新状态的后端、小程序、管理后台，取消 POST 仍关闭。
5. 回归旧订单、付款、建任务、任务动作、列表和详情读取。
6. 三端兼容验证通过后，才开启开发环境取消 POST，并执行受控演示数据验证。

## 恢复路径 A：尚无 M8 写入

前提必须同时满足：三张 M8 表均为 0 行；不存在取消订单/事件/任务状态。

1. 先关闭取消 POST，并关闭预览入口进入维护窗口；停止 Nginx、M8 `print-backend.service` 及任何隔离候选进程，等待进程 cgroup 清空。MySQL 保持运行供受控 DDL 使用。
2. 使用 `ops/db/rollback-m8-no-writes-controlled.sh --execute <已核对数据库名>`。执行器持有共享构建锁，要求后端和 Nginx 已 inactive，目标库没有其它连接或活动事务，才向 SQL 会话设置排空凭据并执行零写入断言。任何一步失败即停止，服务保持维护状态；不得跳过门禁手工 DROP。
3. SQL 在受控维护窗口内先检查三表、订单、事件和任务均无 M8 写入，再删除兼容表并恢复 M7 CHECK。检查与 DDL 期间没有应用进程或数据库连接可提交在途请求，避免零行检查后晚提交。
4. 在恢复流量前切换并核对 M7 后端、小程序与管理端产物；M8 读取路径依赖取消表，删表期间不得恢复 M8 进程或流量。
5. 启动 M7 后端，等待健康端点及旧订单读取通过，再恢复 Nginx；验证旧付款和任务链路，保留备份与执行证据。

## 恢复路径 B：已经存在任一 M8 写入

禁止执行回退脚本、禁止恢复旧备份、禁止恢复旧 CHECK、旧后端或旧前端解析器。

1. 立即关闭取消 POST，保留 GET 和兼容读。
2. 保留新 schema、取消/退款/人工核实记录及不可变账本。
3. 记录故障窗口、受影响订单和当前状态；不得自动退款、重打或改人工结论。
4. 以兼容读取版本前向修复，经相同级别审查和验证后再恢复写入。

## 验证边界

- 模拟退款只证明新系统内部模拟账务闭环，不代表真实资金到账。
- 模拟打印回执不证明纸张实际输出。
- 云端浏览器/API 验证不等于微信真机验收或外部用户验收。
- 本方案没有授权操作原“云途智印”后台或小程序产生数据。
