## 根因与结论

第二次部署中，新后端 readiness 和 pre-enable PDF/单图回归均通过。启用后的空文件探针实际返回 HTTP 400、`code=1934002`、`data=null`；控制器先校验 part 非空与大小，再调用会话校验，因此脚本要求 401/1926003 属于探针预期错误。

关闭状态由前置 Filter 返回 404/1934001；开启后空文件到达控制器返回 400/1934002。该差异足以证明“启用后路由可达”，但不能证明匿名鉴权、渲染或业务闭环。

最终提交相对基线只有两处变化：HTTP 401 改为 400，业务码 1926003 改为 1934002。Bash 语法和离线正反例断言通过；错误状态、错误业务码、非空 data 均拒绝。后续 runtime smoke 仍必须以合法非空匿名请求验证 401/1926003，并以有效会话完成完整闭环。

## 边界

最终 PASS 只授权第三次开发环境部署，不等于部署、HTTP/browser、生产、真机或用户验收通过。
