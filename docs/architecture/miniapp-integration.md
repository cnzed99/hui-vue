# 小程序、服务端与管理后台集成边界

状态：M5 自定义文字打印闭环已部署；文档 PDF、自定义文字生成 PDF、本人订单列表/详情及配套后台模拟处理已实现。真实微信、资金和打印设备仍未接入。

原则：客户端只提交选择和文件引用；价格、订单状态、权限和打印幂等均由服务端负责。

## 三端职责

| 端 | 当前职责 | 后续职责 |
| --- | --- | --- |
| 微信小程序 | 首页、文库、我的、文档打印目录；隔离 PDF 上传、自定义文字生成 PDF、参数确认、报价、订单、模拟支付、结果恢复，以及本人订单列表/详情 | 其余打印类型、文库详情和个人中心业务 |
| 服务端 | 演示会话、文件解析、固定文本排版、权威计价、订单/模拟支付、唯一打印任务、租约/fencing、不可变回执与审计 | 其余业务资源及外部微信/存储/打印适配器 |
| 管理后台 | 查看小程序订单；按权限创建唯一任务、驱动模拟终端状态、查看回执和异常 | 只补充小程序业务闭环必需的配置与处置；纯后台模块下一期 |

## 接口分层

- 用户端前缀：`/app-api/print/miniapp/**`。Nginx 只逐条发布目录、演示会话、PDF/文字文件、报价、订单、模拟支付和打印结果所需的精确路径；兜底 `/app-api/` 继续返回 404。`print-result` 只允许 GET 到达后端，HEAD/POST/OPTIONS 均在代理前拒绝。
- 管理端使用 `/admin-api/print/**`；M4 配套后台接口位于 `/admin-api/print/miniapp-demo/**`，读取与处理权限分离。
- 共用服务层承载文件元数据、解析结果、报价快照、订单、任务和回执；小程序不能绕过服务层直接写管理表。
- 首页、文库、个人中心首批使用本地 fixture；迁移到真实接口时保持响应 DTO 与页面模型解耦。
- 已实现写接口、状态流转和价格规则均以服务端契约、数据库约束和 Astra High 审查为准；后续新增退款、补打、真实终端或新计价维度时必须重新审查相关增量。

### M2 目录接口

- `GET /app-api/print/miniapp/catalog`：匿名、只读、无参数、无数据库访问；仅返回版本、入口、支持扩展名、演示限制和 `uploadEnabled=false`。
- 该 handler 使用方法级 `@PermitAll` 与 `@TenantIgnore`，两者都由框架按准确 handler 路径收集，不增加前缀级匿名或租户豁免。
- H5 通过同源 Nginx 联调；微信构建必须配置已备案的绝对 HTTPS API 基址，未配置时明确使用本地目录并显示服务不可用。
- 小程序严格验证返回字段和正整数约束；非法 JSON、非 200 或超时均回退，不得显示为服务端已连接。

## 目标闭环

1. **选择打印类型**：文档打印首个闭环已实现；图片、照片、证件照、扫描复印和压缩包等仍为后续批次。
2. **上传文件**：开发演示采用服务端私有存储，单 PDF 不超过 2MB、20页、暂存1小时；对象存储只保留适配器边界。
3. **解析**：服务端异步校验 PDF、统计页数、保存摘要和明确失败状态；原系统不接收任何文件。
4. **计价**：服务端按门店价格版本、每文件总纸张和阶梯规则生成冻结报价；客户端不计算最终金额。
5. **创建订单**：按报价快照创建持久化订单、item 和事件；主体隔离、幂等与并发约束已验证。
6. **模拟支付**：只生成明确标识的模拟收据和借贷平衡记录，不调用微信支付、不扣真实资金。
7. **后台处理**：具备 `print:order:process` 的管理员创建唯一任务，按 QUEUED→CLAIMED→ACCEPTED→EXECUTING 推进；只读角色不能处理。
8. **模拟打印回执**：成功/失败回执不可更新或删除；租约过期和未知结果不自动重打。真实打印端仍为外部依赖。
9. **小程序查看结果**：当前小程序主体只能查询自己的订单、任务和回执；重新进入确认页可恢复模拟支付及打印结果，“我的订单”可分页查看本人订单并进入详情。

## M5 自定义文字接口与隐私边界

- `POST /app-api/print/miniapp/demo/text-files`：只接受严格 `application/json`，正文最多 10000 个 Unicode code point、60KiB UTF-8；必须携带演示会话和幂等键。同键同正文返回同一文件，同键不同正文固定冲突；并发渲染有界，繁忙时返回固定 429 业务码。
- 服务端以受控文泉驿正黑字体、固定 A4 排版和版本标识生成 PDF；生成结果进入既有私有文件暂存与解析链，不把正文写入数据库、文件名、URL、响应、访问日志或错误日志。小程序只把解析后的文件元数据写入打印草稿，离开文字页立即清空正文。
- 字体和许可证以固定 SHA 安装到 `/home/ubuntu/print-system/runtime/fonts`，服务运行用户只读；字体、排版版本和 PDF 限额均通过环境配置绑定。AppID、真实对象存储和打印端不因此视为已接入。
- `GET /app-api/print/miniapp/demo/print-result?orderId=...`：只有 GET 可代理；服务端再按有效会话、tenant、store、principal 和 orderId 查询。跨主体与不存在结果保持隐藏，响应禁止缓存。
- API 40/40、真实后端重启 7/7 和页面闭环 11/11 均通过；具体证据路径记录在 `docs/plans/miniapp-roadmap.md`。这些结果只证明回环开发环境，真实支付、真实打印、微信真机和外部验收继续 `NOT_RUN`。

## M5 订单中心接口与发布边界

- `GET /app-api/print/miniapp/demo/orders?pageNo=1&pageSize=20`：演示会话必需；参数只允许规范十进制的 pageNo 1–10000、pageSize 1–20。服务端在一个只读 `REPEATABLE_READ` 事务中完成当前 tenant/store/principal 的 count、list 和详情映射。
- `GET /app-api/print/miniapp/demo/order?id=...`：复用既有本人详情；跨主体与不存在订单同为 `ORDER_NOT_FOUND`，避免存在性旁路。
- Nginx 仅在精确 `/orders` 路径放行 GET/POST，继续拒绝其它方法、转发 Authorization 并禁止缓存；兜底 `/app-api/` 未放宽。
- 小程序按 id 去重分页结果，刷新重置页码；页面隐藏、切会话或请求代次变化会清空旧主体数据。支付/打印的独立查询失败不会伪装为“未支付”或“未建任务”。
