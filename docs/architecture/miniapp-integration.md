# 小程序、服务端与管理后台集成边界

状态：第一版架构基线，关键业务写入尚未实现。

原则：客户端只提交选择和文件引用；价格、订单状态、权限和打印幂等均由服务端负责。

## 三端职责

| 端 | 当前职责 | 后续职责 |
| --- | --- | --- |
| 微信小程序 | 首页、文库、我的、文档打印目录、仅本机文件元数据与演示解析状态 | 文件上传、参数确认、报价、模拟支付、订单与结果查询 |
| 服务端 | 复用现有基础设施；提供静态非敏感小程序目录 | 文件解析、计价、订单状态、回执与审计 |
| 管理后台 | 运营管理页面与小程序目录连通状态 | 处理订单、查看解析结果、模拟打印、查询回执与异常 |

## 接口分层

- 用户端前缀规划：`/app-api/print/**`；当前 Nginx 只精确发布 `GET /app-api/print/miniapp/catalog`，其它 `/app-api/` 路径不代理。
- 管理端继续使用：`/admin-api/print/**`。
- 共用服务层承载文件元数据、解析结果、报价快照、订单、任务和回执；小程序不能绕过服务层直接写管理表。
- 首页、文库、个人中心首批使用本地 fixture；迁移到真实接口时保持响应 DTO 与页面模型解耦。
- 所有写接口、状态流转和价格结果在实现前补齐契约与审查，不以本文件中的流程名称替代最终业务规则。

### M2 目录接口

- `GET /app-api/print/miniapp/catalog`：匿名、只读、无参数、无数据库访问；仅返回版本、入口、支持扩展名、演示限制和 `uploadEnabled=false`。
- 该 handler 使用方法级 `@PermitAll` 与 `@TenantIgnore`，两者都由框架按准确 handler 路径收集，不增加前缀级匿名或租户豁免。
- H5 通过同源 Nginx 联调；微信构建必须配置已备案的绝对 HTTPS API 基址，未配置时明确使用本地目录并显示服务不可用。
- 小程序严格验证返回字段和正整数约束；非法 JSON、非 200 或超时均回退，不得显示为服务端已连接。

## 目标闭环

1. **选择打印类型**：小程序选择文档、图片、照片等业务入口；当前仅页面入口。
2. **上传文件**：向对象存储申请临时上传凭证并回传文件引用；当前只预留适配器，不上传。
3. **解析**：服务端异步解析页数、尺寸、文件类型和可打印性，返回可解释的失败原因。
4. **计价**：服务端依据已审查的门店价格规则生成带版本的报价快照；客户端不得自行计算最终金额。
5. **创建订单**：以报价快照和文件引用创建订单；必须在实现前完成权限、幂等和并发审查。
6. **模拟支付**：一期只允许明确标识的模拟支付适配器；不得调用微信支付或伪造真实交易凭据。
7. **后台处理**：管理后台读取订单并执行受控处理；领取、重试、退款等状态规则另行审查。
8. **模拟打印回执**：服务端接收模拟终端回执并保留审计链；真实打印端仍为外部依赖。
9. **小程序查看结果**：用户查询自己的订单、处理状态和回执摘要。

## 第一批数据边界

- 首页、文库、个人中心继续使用本地只读数据；文档打印目录优先读取上述静态服务端接口，失败时使用可识别的本地 fallback。
- 不写数据库，不调用原后台或原小程序接口，不上传对象存储。
- 任何新增后端写入、权限作用域、并发状态或关键规则，按项目 `AGENTS.md` 即时独立审查。
