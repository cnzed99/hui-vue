# 小程序、服务端与管理后台集成边界

状态：M8 取消、全额模拟退款与人工核实已完成开发环境部署；文档 PDF、自定义文字、原创演示文库、单图片、本人订单列表/详情及配套后台模拟处理均已实现。真实微信、资金和打印设备仍未接入。

原则：客户端只提交选择和文件引用；价格、订单状态、权限和打印幂等均由服务端负责。

## 三端职责

| 端 | 当前职责 | 后续职责 |
| --- | --- | --- |
| 微信小程序 | 首页、文库、我的、文档打印目录；隔离 PDF/单图片上传、自定义文字生成 PDF、参数确认、报价、订单、模拟支付、取消/模拟退款、结果恢复，以及本人订单列表/详情 | 多图片拼版、照片/证件/扫描等打印类型和个人中心业务 |
| 服务端 | 演示会话、PDF 解析、固定文本与单图片转 PDF、权威计价、订单/模拟支付、取消/模拟退款/人工核实、唯一打印任务、租约/fencing、不可变回执与审计 | 其余业务资源及外部微信/存储/打印适配器 |
| 管理后台 | 查看小程序订单、取消/退款/人工核实记录；按权限创建唯一任务、驱动模拟终端状态、查看回执和异常 | 只补充小程序业务闭环必需的配置与处置；纯后台模块下一期 |

## 接口分层

- 用户端前缀：`/app-api/print/miniapp/**`。Nginx 只逐条发布目录、演示会话、PDF/文字/单图片文件、报价、订单、模拟支付和打印结果所需的精确路径；兜底 `/app-api/` 继续返回 404。`print-result` 只允许 GET 到达后端，HEAD/POST/OPTIONS 均在代理前拒绝。
- 管理端使用 `/admin-api/print/**`；M4 配套后台接口位于 `/admin-api/print/miniapp-demo/**`，读取与处理权限分离。
- 共用服务层承载文件元数据、解析结果、报价快照、订单、任务和回执；小程序不能绕过服务层直接写管理表。
- 首页、文库、个人中心首批使用本地 fixture；迁移到真实接口时保持响应 DTO 与页面模型解耦。
- 已实现写接口、状态流转和价格规则均以服务端契约、数据库约束和 Astra High 审查为准；后续新增退款、补打、真实终端或新计价维度时必须重新审查相关增量。

### M2 目录接口

- `GET /app-api/print/miniapp/catalog`：匿名、只读、无参数、无数据库访问；仅返回版本、入口、支持扩展名、演示限制和 `uploadEnabled=false`。
- 该 handler 使用方法级 `@PermitAll` 与 `@TenantIgnore`，两者都由框架按准确 handler 路径收集，不增加前缀级匿名或租户豁免。
- H5 通过同源 Nginx 联调；微信构建必须配置已备案的绝对 HTTPS API 基址，未配置时明确使用本地目录并显示服务不可用。
- 小程序严格验证返回字段和正整数约束；非法 JSON、非 200 或超时均回退，不得显示为服务端已连接。

## 目标闭环

1. **选择打印类型**：文档打印首个闭环已实现；图片、照片、证件照、扫描复印和压缩包等仍为后续批次。
2. **上传文件**：开发演示采用服务端私有存储，单 PDF 不超过 2MB、20页、暂存1小时；对象存储只保留适配器边界。
3. **解析**：服务端异步校验 PDF、统计页数、保存摘要和明确失败状态；原系统不接收任何文件。
4. **计价**：服务端按门店价格版本、每文件总纸张和阶梯规则生成冻结报价；客户端不计算最终金额。
5. **创建订单**：按报价快照创建持久化订单、item 和事件；主体隔离、幂等与并发约束已验证。
6. **模拟支付**：只生成明确标识的模拟收据和借贷平衡记录，不调用微信支付、不扣真实资金。
7. **后台处理**：具备 `print:order:process` 的管理员创建唯一任务，按 QUEUED→CLAIMED→ACCEPTED→EXECUTING 推进；只读角色不能处理。
8. **模拟打印回执**：成功/失败回执不可更新或删除；租约过期和未知结果不自动重打。真实打印端仍为外部依赖。
9. **小程序查看结果**：当前小程序主体只能查询自己的订单、任务和回执；重新进入确认页可恢复模拟支付及打印结果，“我的订单”可分页查看本人订单并进入详情。
10. **取消与模拟退款**：未付款订单可取消；已模拟付款且任务从未领取时全额反向记录模拟退款；任务已领取或结果不明时只登记人工核实，原任务不自动停止、不自动退款、不自动重打。

## M5 自定义文字接口与隐私边界

- `POST /app-api/print/miniapp/demo/text-files`：只接受严格 `application/json`，正文最多 10000 个 Unicode code point、60KiB UTF-8；必须携带演示会话和幂等键。同键同正文返回同一文件，同键不同正文固定冲突；并发渲染有界，繁忙时返回固定 429 业务码。
- 服务端以受控文泉驿正黑字体、固定 A4 排版和版本标识生成 PDF；生成结果进入既有私有文件暂存与解析链，不把正文写入数据库、文件名、URL、响应、访问日志或错误日志。小程序只把解析后的文件元数据写入打印草稿，离开文字页立即清空正文。
- 字体和许可证以固定 SHA 安装到 `/home/ubuntu/print-system/runtime/fonts`，服务运行用户只读；字体、排版版本和 PDF 限额均通过环境配置绑定。AppID、真实对象存储和打印端不因此视为已接入。
- `GET /app-api/print/miniapp/demo/print-result?orderId=...`：只有 GET 可代理；服务端再按有效会话、tenant、store、principal 和 orderId 查询。跨主体与不存在结果保持隐藏，响应禁止缓存。
- API 40/40、真实后端重启 7/7 和页面闭环 11/11 均通过；具体证据路径记录在 `docs/plans/miniapp-roadmap.md`。这些结果只证明回环开发环境，真实支付、真实打印、微信真机和外部验收继续 `NOT_RUN`。

## M6 文库目录、详情与去打印边界

- `GET /app-api/print/miniapp/demo/library`：匿名只读固定原创演示目录；只允许白名单分页、关键词、静态分类和排序参数，不访问真实租户/门店数据，不写浏览或打印统计。
- `GET /app-api/print/miniapp/demo/library-entry`：只返回原创预览页和 capability；不返回原系统文件、对象存储 URL、token 或真实统计。
- `POST /app-api/print/miniapp/demo/library-files`：必须有效演示会话、Origin/Host、幂等键和严格 JSON；客户端只能提交固定 `entryId`。服务端以冻结 `entryId + contentVersion` 组装受信文本，共用同一 renderer 和文件链；同键换条目/版本冲突。
- 小程序只在文件 `READY`、未过期且解析页数与固定预览一致时写入 `SERVER_UPLOAD` 草稿；网络重试保持同一幂等键，`FAILED/DELETED` 不自动重建。
- Nginx 只增加上述三个精确路径；GET 入口显式拒绝 HEAD，写入限制 2KiB 并复用文件生成限流区，相邻路径仍 404。
- 本批不增加数据库表、计价算法、支付、订单状态或打印任务规则；收藏、真实分享、真实门店文库和“本店/不限”筛选继续未完成。
- `evidence/miniapp/m6-library-runtime-20261031T111307Z.json`：26/26 API 运行检查通过；`evidence/miniapp/m6-library-browser-closed-loop-20261102T035337933Z-0f4c6fb1/report.json`：17/17 页面闭环通过。
- 最终 Astra High 独立复审 `PASS`，只批准当前冻结 `entryId + contentVersion=v1` 候选提交开发分支；真实支付、真实打印、微信真机及外部验收继续 `NOT_RUN`，不构成正式上线批准。

## M7 单图片转 PDF 与部署边界

- `POST /app-api/print/miniapp/demo/image-files`：只允许有效演示会话、正确 Origin/Host、幂等键和单个 multipart 文件。当前只接受实际可解码的 JPEG/PNG；扩展名和 MIME 声明不能替代格式验证。
- 服务端在有界子 JVM 中处理图片，纠正 EXIF 1–8、PNG 透明铺白，并按 A4 纵向等比 contain 生成确定性单页 PDF。2MB 输入、1200 万像素、单边 8192、2MB 输出、10 秒和 1 并发均由服务端配置约束。
- 生成 PDF 复用既有私有文件暂存、解析、权威报价、订单、模拟支付、唯一打印任务和模拟回执；没有修改计价算法、支付/退款、权限作用域、任务状态机或防重复规则。
- Nginx 只增加精确图片入口，限制 POST、请求体、连接和速率；无会话探针必须得到 `HTTP 401 + code 1926003`，缺 Origin 的 403、框架包装 200、非 JSON 和 5xx 均不能算路由健康。
- 部署脚本持有与标准构建相同的全窗口锁，快照配置和链接后再切换；失败回滚必须核对旧配置哈希、旧链接、四服务 active 和健康 JSON，无法证明恢复时报告 `ROLLBACK_FAILED`。
- `evidence/miniapp/m7-image-full-loop-20261102.json` 证明近像素上限 JPEG 经边缘入口到 READY，再复用既有报价、订单、模拟支付、后台任务、模拟回执和结果查询；云端 H5 浏览器 7/7 验证选择预览、上传、READY 和进入共用设置。微信真机、真实支付/退款、真实打印机和外部验收仍为 `NOT_RUN`。

## M8 取消、模拟退款与人工核实边界

- `GET /app-api/print/miniapp/demo/cancellation` 始终保留本人只读恢复；`POST /app-api/print/miniapp/demo/cancellations` 由独立功能开关控制，要求有效演示会话、幂等键、严格订单版本和当前主体作用域。
- 只有未付款订单、已模拟付款但未建任务、或仍处于首次 `QUEUED/fence=0` 的任务允许自动取消；后两者全额反向记录模拟门店借方和模拟用户贷方。曾领取、执行、成功、失败或结果未知的任务只能登记不可变人工核实快照。
- 取消、退款和任务状态在同一事务及固定锁顺序内提交；数据库 CHECK、外键和不可变触发器阻止伪造退款、单边账、错误任务状态或事后修改。
- 管理后台只读展示申请时快照、当前任务和退款凭证，不提供自动核实、重打或真实退款按钮；已取消订单不能再创建或推进打印任务。
