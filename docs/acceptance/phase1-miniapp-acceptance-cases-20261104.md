# 一期小程序＋配套后台简明验收用例（2026-11-04）

状态：`READY_FOR_USER_TEST`。本文列出当前已部署开发候选可由用户手工验证的功能；勾选前不视为用户验收通过。

## 入口与边界

- 小程序 H5：`http://127.0.0.1:18080/miniapp/`
- 配套后台：`http://127.0.0.1:18080/login?redirect=/print/demo-orders`
- 两个地址均通过本机 SSH 隧道访问；登录使用现有演示管理员，不在文档保存账号或密码。
- 支付、退款、打印回执均为**模拟**；微信真机、真实资金、对象存储和真实打印机保持 `NOT_RUN`。

## 配套后台用例

| ID | 操作 | 预期结果 | 当前范围 |
| --- | --- | --- | --- |
| AD-01 | 登录后进入开发订单列表，按订单号查询 | 能看到小程序创建的同一订单；无权或不存在对象不泄露详情 | 可验收 |
| AD-02 | 打开订单详情，创建模拟打印任务 | 同一订单只能形成一个稳定任务；按钮明确不会驱动真实打印机 | 可验收 |
| AD-03 | 依次执行“领取→受理→开始执行→模拟成功” | 每一步状态和版本递增；小程序详情最终显示同一模拟成功回执 | 可验收 |
| AD-04 | 选择模拟失败或结果未知 | 小程序准确显示失败或人工核实，不自动补打 | 可验收 |
| AD-05 | 打开取消/模拟退款记录 | 能区分未付款取消、领取前模拟退款和领取后人工核实 | 可验收 |
| AD-06 | 对同一动作快速重复点击或使用旧页面再次提交 | 重复请求不产生第二任务或第二回执，界面提示版本冲突/刷新 | 可验收 |

## 建议验收顺序

1. 先执行 MP-01、MP-02、MP-03、MP-04。
2. 在后台执行 AD-01、AD-02、AD-03。
3. 回小程序执行 MP-05，确认显示同一订单和模拟成功结果。
4. 再分别执行取消分支 MP-06～MP-08，以及文字、文库、图片、拼版、ZIP、文件复印和证件照。
5. 每项记录“通过/失败/未测”，失败时保留页面、时间、订单号后四位和操作步骤，不发送令牌或密码。

## 完成判定

- 表中“可验收”表示已有开发和自动化证据，不等于用户已验收。
- MP-15 只证明证件照服务端文件生成，不证明照片纸计价和订单闭环。
- MP-16 只证明安全边界，不应勾选为对应业务功能完成。
- 一期最终完成仍要求剩余照片冲印、权益/服务、微信发布条件和固定回归门槛另行收口。
