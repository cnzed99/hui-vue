## 文件与操作

- 执行：`python3 ops/backup/backup_verify.py`。每次建立新的加密一致性备份并验证隔离恢复；如存在非InnoDB表，脚本会拒绝将其当成事务一致性快照。
- 加密备份：`runtime/backups/print-demo-*.sql.aesgcm`，权限0600。
- AES密钥：`runtime/secrets/database-backup-aes256.key`，32随机字节，权限0600。不得输出、提交Git、写入聊天或与普通源码包一起传输。
- 格式：`PRINTDB1\0`文件头＋12字节随机nonce＋AES-GCM密文/认证tag；AAD固定为 `print-system:print_demo:mysql-snapshot:v1`。恢复必须使用该格式、原密钥、完整密文和AAD，任一不符应拒绝，不允许跳过认证。
- 当前采用内存处理，小库上限128 MiB；若未来超过上限需实现认证加密流式备份，不能直接取消上限让4 GB机器承受无界内存。
- 大操作前要求至少10 GiB空闲。验证脚本不扩大运行数据库用户权限；schema导出/独立恢复使用既有sudo数据库管理员权限。

## 保留与清理

`runtime/backups/owned-manifest.json`只记录本脚本已通过恢复验证的备份。保留最近2份；删除前校验精确文件名、非符号链接及密文SHA256。未知文件和校验不一致的文件不自动删除。失败后保留的未注册备份需要人工检查后决定，不能以通配符批量清空。测试不创建明文SQL，临时库在finally中按本次唯一名称删除。

## 仍需完成

这是同一台服务器内的逻辑备份和隔离恢复验证，**不是异地备份，也没有证明整机故障后的恢复能力**。密钥与备份都在同机，系统盘损坏会同时丢失。后续交付需把加密备份和单独保护的密钥保存到另一受控位置，并测试从该位置取回；需另行验证应用文件、上传文件、配置和数据库的一致性恢复。

正式灾难恢复应在隔离的新数据库中先完成认证解密、导入及业务核验，确认后再切换服务配置；本脚本只创建并删除临时验证库，不覆盖线上同名数据库。
